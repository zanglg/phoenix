# Phoenix 0.2 development review contract

This describes `0.2.0-dev.0`, developed on `dev`. It is a review boundary, not an
accepted formal 0.2 release. The immutable 0.1 tag and its contract remain separate.
The new implementation retains the 0.1 memory, executable, filesystem and device
limits except for the user-execution changes stated here.

## Execution and ownership

- One CPU, pinned AArch64 QEMU virt-9.1/Cortex-A72/GICv3/TCG, 512 MiB, 4 KiB pages.
- At most two user processes: init and one child. Both may be runnable, each with
  its own ELF/stack/root/ASID, complete integer context and eight regular FDs.
- Round-robin user scheduling uses a 2 ms physical-timer quantum. EL0 permits
  IRQs; vector entry masks DAIF, and all EL1 syscalls complete before switching.
  Kernel work and emulator scheduling can extend a quantum. No hard real-time
  guarantee, kernel preemption, nested IRQs, SMP or FP/SIMD context is provided.
- User contexts are copied as owned values at the exception epilogue. No blocked
  Rust continuation or borrowed kernel object crosses a context switch. The
  permanent shared boot/exception stack also hosts a naked, stack-neutral EL1h
  WFI loop when no process is runnable. It is not a general kernel-thread stack.
- Child exit/fault leaves an unschedulable terminal record until wait. Parent
  root installation/readback and global TLB completion precede frame/ASID reuse.
  Waiting results are published before wake/selection. Reap revokes process and
  queue identities and restores the exact allocator/ASID/slot baseline.
- Init exit/fault terminates the whole system and revokes IRQ delivery. Any
  remaining child owners stay retained until machine halt. No orphan/reparenting,
  process cancellation, signal delivery or arbitrary process tree is provided.

## Native ABI additions

The ABI remains native, unstable revision 0: SVC #0, x8 number, x0–x5 arguments,
x0 result, other GPRs preserved. Existing calls 0–5 retain their contracts.

| Call | Arguments and result |
| --- | --- |
| 6 spawn | `(path, length)` creates init's sole child and returns 0. EAGAIN while any child, including a zombie, exists or if called by a child. No descriptor inheritance or exposed PID handle. |
| 7 wait | No arguments; consumes the caller's sole child outcome. Returns its representable status or EFAULT for a terminal fault. Blocks until completion; ECHILD when none belongs to the caller. |
| 8 yield | No arguments; returns 0 when selected again. |
| 9 sleep | `(nanoseconds)`; zero yields. Positive values at most 1,000,000,000 use checked rounded-up counter conversion, retain all resources and return 0 no earlier than the deadline. Larger/overflowing values return EINVAL before state changes. |

Sleep is not interruptible by signals. Expired sleepers become Ready at a sampled
counter instant and then follow round robin; lateness is unbounded by this
experimental contract. The explicitly IRQ-disabled diagnostic boot mode rejects
positive sleep with ENOSYS. Normal/interactive system boots provide a wake source.

Console and file operations remain bounded and serialized in kernel dispatch.
Paths, I/O limits, ELF subset, private guarded four-page user stacks, RAM filesystem
capacity and native initial stack layout retain the 0.1 contract. The focused
first-init probe retains its smaller syscall subset and is a separate image.

## Observed gate

Local preflight uses Rust 1.99.0, QEMU 10.0.13 and the debug profile. It passes
236 kernel tests and 22 tooling tests, all 29 QEMU launches, and independent Rust
1.95 checks/tests. The scheduling suite requires:

- 64 cooperative rounds and the same workload with timer preemption: 257 child
  reaps/128 exact faults in each, context/stack/FD isolation and both wait orders;
- non-yielding init plus an infinite child, all 31 GPRs/NZCV/SP/private-word
  checks, multiple IRQs per context, real handoffs and a still-runnable child;
- rejection of the same successful guest when timer preemption is disabled;
- 16 overlapping sleep rounds, 32 paired counter-derived deadlines/wakes,
  nonzero idle IRQs, stable exception-stack top and exact reaping;
- existing 705-lifetime/576-fault hardening, low-frame/backend/ASID failure
  rollback, nine distinct protection faults and wrong-fault negative control.

Exact clean-source/package/CI identity belongs to the retained validation receipt.
These checks cover the stated workloads, not arbitrary hardware, optimized release
builds or a stable userspace ABI. Formal release still requires owner review.
