# Decisions made while completing the 0.1 path

## Image reservation and permission window

The system image's 1 MiB construction stack ends at 0x40207000 in the first
unoptimized build, seven pages past the former whole-image limit. The limit
is refined rather than changing page size or enlarging the stack: text,
rodata and the stack guard must still end inside RAM's first 2 MiB, while
ordinary RW/NX data and the stack tail may extend up to RAM + 4 MiB. The
existing direct-map policy already maps that tail as normal RW/NX memory.
Both the linker and ELF inspector enforce these separate limits. No additional
translation table, permission relaxation or physical-load-address change is
needed. The full image, including its tail, remains reserved from allocation.

## Minimal native system

The first system uses the existing userspace package for three independently
linked ELF binaries (init, child, and an intentional fault program). No external
dependency or new architecture is introduced. Native syscall 5 runs one child
synchronously; the parent enters Waiting until child exit or fault, root
replacement, complete TLB invalidation, and frame reclamation finish. A child
cannot recursively run another child. This is a bounded single-CPU process model;
concurrent userspace scheduling and POSIX fork/exec are outside this release.

The shared root exposes read-only initramfs and a fixed-capacity `tmp/` mount.
Mode 0 opens for reading; mode 1 creates/opens a read/write tmp file without
truncation. Eight 1024-byte tmp files and eight regular descriptors per process
are hard limits. Writes are atomic with respect to capacity failures; a read
advances its offset only after checked user copying succeeds. Stdin is polled
nonblocking and returns error 11 when empty. Stdout/stderr are polled PL011.
All syscalls run with local IRQs masked and retain no raw user pointers.

Kernel threads separately use a fixed-capacity round-robin policy, guarded
32 KiB stacks, a 2 ms timer quantum, sleep and explicit exit. Context switching
occurs only at the exception epilogue after device locks and Rust borrows end.
The boot thread serves as idle and reaps exited worker stacks after closing IRQ
entry. SMP and nested interrupts remain deferred.

## ASID retirement and fault recovery

The system uses the lowest-free nonzero 8-bit ASID. Reuse requires replacing the
old root, complete global TLB invalidation and consuming the old process owner;
the unsafe retirement API also permits an allocated but never-installed root.
The original never-reuse behavior remains when callers do not retire IDs. This
avoids a lifetime limit of 255 program executions. Every system root switch reads
back TTBR0, and different child programs repeatedly use ASID 2 after retirement.

For 0.1, recoverable user faults mean terminating the faulty child and resuming
its parent with EFAULT. Demand paging, signals, TLS and concurrent user scheduling
remain deferred. The contract does not promise resumption at a faulting instruction.

## Diagnostics and bounded kernel integration

Forced AArch64 frame pointers support a sixteen-frame, bounds-checked trace.
Boot and exception assembly terminate chains; diagnostics never follow raw EL0
frame pointers. A 32-event IRQ-locked ring reports overwritten records explicitly.
Offline lookup uses the exact kernel ELF and bundled llvm-nm; no new dependency
or crate was added.

Kernel workers and the guarded heap are exercised in the focused final-map image;
the minimal user-system image retains its synchronous dispatcher and fixed storage.
Neither supports concurrent userspace or a general-purpose global allocator.
The release contract makes this integration boundary explicit.
