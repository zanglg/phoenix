# 0.2 user scheduling design

Authorized on 2026-10-15; development stays on `dev`. The immutable 0.1 contract
describes the released tag. This document records the evolving 0.2 design and
must distinguish planned behavior from observed target evidence.

## pre.1 boundary

The cooperative checkpoint is Host Tested, Cross Compiled, ELF Inspected and
Runtime Verified on the pinned board: 234 kernel tests, 20 tooling tests and
25 QEMU launches across the complete suite. It remains under the development
version until candidate packaging/review is requested.

The existing `Scheduler` selects one of two user contexts: init and at most one
child. Scheduling is cooperative initially. Local IRQs remain masked throughout
EL0 and EL1 until the separately validated pre.2 step. No blocked Rust stack or
kernel lock survives a switch. Each process owns a full saved `ExceptionFrame`;
the permanently retained boot/exception stack is shared only across completed,
non-reentrant dispatch operations. Independent kernel stacks become necessary
if a future syscall suspends an in-progress kernel continuation.

The run queue holds generation-checked scheduling identities. The process table
holds generation-checked process identities and owns roots, ASIDs, files and
saved frames. Their binding is published only after construction. A running
context is saved before it becomes Ready or Waiting. A selected Ready process
becomes Running before its frame is restored. Waiting parents are Blocked in
the queue; terminal children are Exited there and cannot be selected.

## Native interface decision

Retain calls 0–5 and the synchronous `run(path, length)` result. Add the following
native, unstable operations to the system image (the focused init probe keeps
its original subset):

| Number | Operation | Contract |
| --- | --- | --- |
| 6 | spawn(path, length) | Root init creates its single child; returns 0 while both are runnable. EAGAIN if a child already exists or the caller is itself a child. |
| 7 | wait() | Root init consumes its single child's completion, blocking if necessary. Returns exit status or EFAULT for a terminal fault; ECHILD if no child belongs to the caller. |
| 8 | yield() | Save the caller, choose the next Ready process, return 0 when selected again. |

Path and image validation retain existing limits and errors. Spawn does not
inherit descriptors. A completed child retains its terminal record and resources
until wait; the one-child capacity remains occupied meanwhile. No PID is exposed
by these calls, so there is no reusable user-visible PID handle. Nested children,
general waitpid, asynchronous events and arbitrary process trees are deferred.

Init exit terminates the whole system, as in 0.1; any remaining child is never
scheduled again and its owners remain retained until machine halt. This is not
a general orphan/reparenting model. A child that never yields can still monopolize
the CPU during pre.1; pre.2 must remove that limitation.

## Completion and memory ordering

A child exiting or faulting becomes terminal before scheduling another process.
The parent's root is installed and global TLB invalidation completes before child
frames or ASIDs can be reused. If the parent has not waited, retain the zombie;
if it is waiting, publish the result into its saved frame, retire child owners,
then wake and select the parent. Reaping revokes queue identity and process
identity as well as releasing frames and ASID. IRQ masking serializes every
transition on one CPU; no SMP or nested exception safety is inferred.

## pre.2 timer extension

Normal system/stress boots now use a 2 ms physical timer. Every initial process
frame uses EL0t with D/A/F masked and I clear (SPSR 0x340). The focused cooperative
boot retains I masked to preserve deterministic cooperative handoff evidence.
Vector entry masks DAIF before saving state or entering Rust. EL1 never enables
IRQs, so all syscalls and process/queue/VFS mutations complete without preemption.
The timer dispatch returns only after EOI and release of runtime/timer locks;
only then does the outer dispatcher copy/select a process frame. No lock guard,
Rust continuation or borrowed user memory crosses ERET. Kernel execution latency
can extend a quantum; this is not a hard real-time guarantee.

Each fired timer must match the retained TimerId and scheduler event before
rearming. Root exit cancels the pending timer and closes GIC delivery. Statistics
count root/child-slot timer entries and actual timer-induced process changes.
The non-yielding conformance loop checks all 31 GPRs, NZCV, SP and private words
without any syscall; the child remains in that loop forever. Init must still
finish, and the oracle requires multiple ticks in each context, real handoffs
and a still-runnable child. A second boot disables the timer and must be rejected
even though init can produce the same success text without ever running its child.

## Validation gate

The pre.2 development checkpoint has passed its scoped runtime checks. Sleep and
idle are the next implementation step; formal release/candidate gates are separate.

pre.1 requires actual target execution for repeated cooperative handoffs,
child-exit-before-wait and wait-before-child-exit, fault completion in both orders,
register/stack/descriptor isolation, full-slot rejection, stale process rejection
and exact allocator/ASID/queue recovery. Existing 0.1 positive and negative oracles
must continue to pass. Runtime evidence is recorded in RUNTIME_VALIDATION.md.

pre.2 additionally requires timer-driven switching of non-yielding user code,
complete integer/control-state preservation, post-EOI dispatch and root ownership
checks. Sleep/idle and broader blocking semantics are a subsequent gate.
