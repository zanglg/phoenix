# Phoenix 0.1 technical contract

The supported machine is AArch64 QEMU `virt-9.1`, Cortex-A72, TCG, GICv3,
512 MiB RAM and one CPU. The page size is 4 KiB. EL2 direct boot is normalized
to EL1; direct EL1 boot is tested too. Rust uses the soft-float target, aborting
panics and forced frame pointers. FP/SIMD, real hardware and SMP are unsupported.

## Images and commands

`cargo xtask run-system` builds and boots the minimal native system. At the
console, type `ok` followed by Enter. Init exercises files, console input,
three normal child executions and nine contained user faults, reports
`PHOENIX_SYSTEM_EXIT status=0 fault=false`, then halts. This is a conformance init.
It accepts CR, LF and CRLF; raw console syscalls do not rewrite input bytes.
`test-system` runs those three inputs, rejects invalid input, and runs a mutant
whose nine incorrect faults must be rejected by an independent host oracle.
Each intended fault requires the exact kind, PC from the linked ELF (or the fixed
NX stack target), FAR and ESR. A successful guest exit alone cannot pass a test.

`test-hardening` selects the explicit `phoenix.system-stress` boot argument.
Before EL0, it exercises incomplete frame budgets, every private loader memory/table
operation failure, and unused-ASID exhaustion. The same init ELF's `stress` archive
alias then runs 64 rounds and a final normal child: 705 reaps and 576 faults.
Every child checks frame-set, process-slot and ASID restoration. Child programs
check fresh stack bytes and exhaust/leave open their descriptors; init checks its
retained descriptor/offset and continues after faults and failed loads.

The default `build`/`run` image remains the small boot smoke image. Focused
`test-memory`, `test-kernel-map`, `test-el0` and `test-init` retain their distinct
protocols. `test-runtime` exercises thirteen isolated guest runs, including
exceptions, heap/stack guards, IRQ exclusion, timer delivery and kernel threads.
`ci` includes formatting, checks, Clippy, host tests and all image inspections;
runtime commands are separate; GitHub CI runs both static and QEMU jobs.

The thread/heap conformance image and the user-system image are separate
integration targets. The user-system dispatcher is synchronous with IRQs masked;
it does not schedule user processes concurrently or run the kernel worker probe.
Both targets use the same checked allocator, final-map and exception mechanisms.
A non-cooperating user program can occupy the CPU indefinitely; no user watchdog
or preemption is provided at this boundary.

## Memory and lifetime

The boot DTB and full linker image are reserved before allocation. Final TTBR1
owns eight translation tables, RX text, RO/NX rodata, RW/NX managed RAM and exact
PL011/GIC device pages. The boot stack is 1 MiB with a lower guard. Permission
overrides and that guard fit inside RAM's first 2 MiB; the RW/NX image tail may
reach RAM + 4 MiB. Linker and ELF inspection enforce both bounds.

The fallible kernel heap has four contiguous backing frames and four live
allocation records in its focused integration. Its usable alias begins at
`0xffffff9000101000`, with an unmapped page on either side. All six descriptors
are preflighted before the four leaf writes; TLB completion precedes allocation
use. The heap owner is retained permanently. No global infallible allocator or
concurrent heap consumer is provided.

Sixteen runtime stack slots have eight usable pages (32 KiB) and two guard pages
each. The mapper retains unique frame ownership, checks exact descriptors,
publishes or retires whole leaf batches, and completes TLB maintenance before
release. The two worker test stacks are actually entered, preempted, slept and
reaped; both guards are fault-tested while usable leaves remain mapped. This
size is validated for these bounded workers, not arbitrary future workloads.

## Interrupts and execution

GICv3 and the physical timer have one pinned owner. Publication precedes delivery;
runtime lock precedes timer lock; due-event processing precedes EOI; callbacks
run after device locks are released. The one-shot test proves a pending IRQ
cannot enter an IRQ-locked section and can acquire its lock after restoration.

The kernel scheduler is fixed-capacity round robin with a 2 ms quantum, absolute
sleep deadlines, explicit exit and a retained boot/idle context. Context changes
happen only at the exception epilogue, after Rust borrows and locks end. A complete
288-byte integer/control frame is restored. IRQ nesting and migration are absent;
workers must not yield, sleep or exit while holding a lock or cleanup obligation.

## Processes and native ABI

Revision 0 remains a native, unstable ABI. AArch64 `SVC #0` uses `x8` for the
number, `x0..x5` for arguments, and `x0` for a nonnegative result or negative errno.
Other integer registers are preserved across returning calls.

| Number | Operation | Arguments and result |
| --- | --- | --- |
| 0 | exit | status; never returns |
| 1 | write | fd, pointer, length; byte count |
| 2 | read | fd, pointer, length; byte count or 0 at file EOF |
| 3 | open | path pointer, byte length, mode; fd |
| 4 | close | fd; 0 |
| 5 | run | executable path pointer, byte length; child exit status or error |

Transfers are limited to 256 bytes and canonical relative paths to 128 bytes.
Mode 0 is read-only. Mode 1 creates/opens a writable `tmp/` file without truncation.
Stdin (0) is nonblocking PL011: empty input returns `EAGAIN` (11); stdout/stderr
(1/2) are polled output. Regular descriptors start at 3. There are eight per process.
Errors include `ENOENT` 2, `EIO` 5, `EBADF` 9, `EAGAIN` 11, `ENOMEM` 12,
`EACCES` 13, `EFAULT` 14, `EISDIR` 21, `EINVAL` 22, `EMFILE` 24,
`ENOSPC` 28 and `ENOSYS` 38. Zero-length buffers follow checked user-range rules.

Two process slots hold init and at most one child. `run` suspends the parent in
Waiting; nested child `run` returns EAGAIN. Each image has independently owned
ELF/stack/table frames, four user stack pages, guard holes, descriptors and a
nonzero 8-bit ASID. ELF loading, page population and unpublished allocation are
transactional. Initial argc/argv/envp/minimal auxv use the existing native layout;
dynamic linking, TLS and shared mappings are excluded.

On exit or terminal user fault, the kernel switches to the retained parent root,
completes global TLB invalidation, reaps child frames, retires its ASID, restores
the full parent frame, and resumes it. TTBR0 root/ASID is read back on each switch.
ASID 2 is reused across different programs only after that retirement sequence.
Generation-checked process IDs reject stale handles. Every child reap checks
the allocator's entire free-frame set, remaining ASIDs and process slots against
the pre-child baseline, and confirms the retired PID no longer resolves.

User faults terminate the child and return EFAULT to its parent. They are not
demand-paged or resumed at the faulting instruction. Translation, read/write/execute
permission, illegal instruction, invalid SVC, low RAM/MMIO alias and user-stack
guard faults are tested. Faulting init or a failed conformance check reports its terminal outcome;
unexpected kernel exceptions remain fatal.

## Files and failure behavior

The root combines a read-only, validated `newc` initramfs and a shared in-memory
`tmp/` mount with eight files of at most 1024 bytes each. No deletion, truncation,
directory mutation, seek, credentials or persistent storage is implemented.
All open descriptors use the same retained filesystem owner. Read proposals must
be committed to the originating table while syscall serialization is held.

Reads validate/copy the complete resident user destination before committing file
offsets. Writes validate/copy their complete source before console/file effects.
Tmp writes either fit completely or leave bytes and offsets unchanged. Failed
open preflights descriptor capacity before creating a node. Invalid ranges return
EFAULT without partial cross-page writes. Console input is prevalidated before
consuming bytes. Reclamation scrubs on subsequent population before any new user
mapping is exposed.

## Diagnostics

Fatal exceptions report vector, PC, SPSR, ESR and FAR. Panic/fatal paths dump up
to sixteen validated frame records from the active owned kernel stack. Bounds,
alignment, increasing frame addresses and text return addresses are checked before
each read. Assembly boot/exception boundaries terminate chains. Corruption yields
only a validated prefix; stack overflow has no separate emergency exception stack.

`cargo xtask symbolize <exact-kernel-ELF> <0xADDRESS>...` resolves a containing
text symbol plus offset using the bundled LLVM tools. For a printed return address,
subtract four bytes to identify its call instruction. Always retain the exact ELF.

A 32-record IRQ-locked ring records sequence, raw ticks, kind and two integer
payloads. Kinds are boot (1), process start (2), child reap/ASID (3), user fault (4),
thread switch (5), and one-shot scheduled (6). Oldest records are overwritten with
explicit loss accounting. Panic uses try-lock, copies then unlocks before serial
output, and reports unavailability rather than recursively taking the log lock.

## Release limits

No Linux/POSIX compatibility, persistent storage, networking, SMP, signals,
dynamic linking, real hardware, RISC-V or x86_64 support is implied. Construction
and resource failures have explicit errors or fatal diagnostics. Host failure
injection complements target tests; it does not simulate every possible hardware
failure. The measured compiler, runtime transcripts, unsafe review and artifact
reproduction evidence are linked from [RUNTIME_VALIDATION.md](RUNTIME_VALIDATION.md).
